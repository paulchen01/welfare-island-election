### 1.4 Claude Artifact 專屬 API 與環境功能

全部只出現在 `src/game.js` 最後三行：

```js
function start(d){S=(d&&d.S&&d.S.filter)?d.S:fresh();render()}
window.claude?.hot?.snapshot?.(()=>({S}));
window.claude?.hot?.ready?window.claude.hot.ready(start):start(window.claude?.hot?.data??{});
```

- `window.claude.hot`：Claude 環境提供的狀態保留機制。`snapshot` 登記要保留的遊戲狀態 `S`，`ready` 在頁面重新載入時把保留的狀態交回來。它的確切保留時機與範圍屬於 Claude 環境內部行為，**本次未驗證**。
- 三行都用了 `?.`，`window.claude` 不存在時會直接 `start({})` 開新遊戲，所以**一般瀏覽器不受影響**（已用測試確認）。
- `d.S.filter` 被拿來判斷保留的狀態是否為新版格式。若之後改了 `S` 的結構，要一併調整這個判斷，否則舊格式狀態可能被誤用。
- 遊戲**沒有使用**任何 Artifact runtime capability（`db`、`artifact`、`downloads`、`sample` 等都沒宣告）。

其他瀏覽器 API（非 Artifact 專屬，但有環境差異）：

| API | 位置 | 失效時的行為 |
|---|---|---|
| `navigator.clipboard.writeText` | 結局「複製學習單」 | 失敗時改為顯示文字框並全選，請學生手動複製 |
| `navigator.vibrate` | `buzz()`，選卡、開票、公投 | 包在 try 裡；iOS 不支援，直接略過 |
| `matchMedia('(prefers-reduced-motion: reduce)')` | 輪盤、彩帶、開票數字 | 見 ART_INTEGRATION.md §6 |

**沒有使用** localStorage、fetch、外部 API、Firebase 或任何後端。

## 2. 遊戲架構

### 2.1 入口

- 頁面骨架在 `src/body.html`：`#pips`（屆數進度）、`#hstats`（國債／經濟／貧窮率／民怨）、`#stage`（主舞台）、`#bar`（底部操作列）、`#fx`（彩帶 canvas）。
- 程式入口：`game.js` 最後的 `start()`，建立狀態 `S = fresh()` 後呼叫 `render()`。
- 畫面切換：`render()` 依 `S.phase` 呼叫對應的 `rXxx(stage)` 函式，每次**整個重畫** `#stage` 與 `#bar` 的 innerHTML（沒有框架、沒有虛擬 DOM）。
- 所有按鈕用 `data-a="動作名稱"`，由一個全域 click 監聽器（`game.js` 約 718 行起）分派。

### 2.2 五屆流程與畫面

`S.round` 從 0 到 4（共 `ROUNDS = 5` 屆）。`S.phase` 的值與畫面函式：

| phase | 畫面函式 | 畫面內容 | 離開條件（按鈕 `data-a`） |
|---|---|---|---|
| `title` | `rTitle` | 標題海報（島嶼插畫＋11 位島民）、怎麼玩 | `totitle` → setup |
| `setup` | `rSetup` | 六張政黨卡（口號、特殊能力、兩項政黨目標） | `start`（需先 `choose` 或 `rand`）→ news；同時隨機分配另外五黨給電腦，並抽出 5 位陳情島民 |
| `news` | `rNews` | 上屆「福利島日報」頭條、事件輪盤、社會溫度計（第 2 屆起）、事件新聞與效果、島民現況 | 先 `spin` 抽事件，再 `tobudget`：第 3 屆（round 2）→ ref；第 5 屆（round 4）→ demo；其他 → budget |
| `ref` | `rRef` | 第 3 屆公投：主文、正反方論點、選立場與宣傳經費、開票結果與每位島民的投票 | `refvote` 開票 → `refdone` → budget |
| `demo` | `rDemo` | 第 5 屆人口變遷：5 個族群選民比例改變；阿蒂仍無投票權 | `demook` → budget |
| `budget` | `rBudget` | 政見列、政黨能力、島民即時反應、稅率、既有方案（可刪減）、本屆陳情、10 張手牌 | `count` 公布政見 → results（電腦對手此時才決定政見） |
| `results` | `rResults` | 得票長條、質詢卡（二選一）、當選揭曉、國債變化、選民流向、島民對話泡泡、對手政見 | 先 `answer`，再 `confirm` → 下一屆 news，或 final／imf |
| `imf` | `rImf` | 國家破產畫面（全部島民難過） | `tofinal` → final |
| `final` | `rFinal` | 福利體制揭曉與雷達圖、名次與計分、五屆紀錄、成就徽章、反思學習單、複製學習單 | `restart` → title |

固定節奏：第 1、2、4 屆是一般屆；第 3 屆一定有公投；第 5 屆一定有人口變遷。

| 反思題 | `RQ` | 452 | 3 題 |

每張政策的欄位：

```js
{ id, name, tags:[...], cost,        // cost 負數代表省錢
  d:'說明文字',
  fx:{pov,dec,str,def,stg,env,emp,eco},  // 實施後對全島指標的影響
  cit:{島民id: 支持度變化},              // 提案時對各島民的影響
  say:{島民id: '對話'},                  // 開票後的對話泡泡
  once?:true,   // 一次性（發完就消失，不列入實施中方案）
  ev?:'e3',     // 事件限定
  pet?:'ling',  // 陳情卡
  refOnly?:true // 只會出現在公投
}
```

`fx` 指標代號：`pov` 貧窮、`dec` 去商品化、`str` 階層化、`def` 去家庭化、`stg` 汙名、`env` 環境、`emp` 就業、`eco` 經濟動能。

### 2.4 主要狀態 `S`（`fresh()`，約 307 行）

| 欄位 | 意義 |
|---|---|
| `phase`、`round` | 目前畫面與第幾屆（0–4） |
| `choice`、`assign` | 玩家選的黨；`assign[0]` 是玩家，`assign[1..5]` 是電腦 |
| `event`、`used`、`rot` | 本屆事件、已抽過的事件、輪盤角度 |
| `hand`、`redrawn` | 本屆 10 張手牌、是否已重抽 |
| `platforms[0..5]` | 六黨本屆政見 `{tax, add:[政策id], cut:[政策id], carbon}` |
| `enacted` | **實施中的方案** `[{id, cost}]`（cost 依執政黨折扣後鎖定） |
| `onceUsed` | 已發放過的一次性政策 |
| `history` | 每屆紀錄：事件、六黨政見、各黨滿意度、得票率、收支、執政黨 |
| `debt`、`eco`、`povShock` | 國債、經濟動能、事件造成的貧窮衝擊 |
| `unrest`、`crisis`、`unrestLog` | 民怨值、危機等級（0–3）、每屆民怨紀錄 |
| `govTax`、`lastGov` | 執政黨的稅率與政黨 |
| `q`、`qPick`、`qDebt`、`adj` | 本屆質詢、玩家的回答、回答造成的國債變化、得票加減 |
| `pets`、`pet` | 本局 5 位陳情島民、本屆陳情者 |
| `ref`、`refAlign`、`refSpend` | 公投題目／立場／經費／結果、立場對島民的影響、宣傳花費 |
| `wmod`、`demoDone` | 第 5 屆新的選民比例 |
| `lastProbs` | 上屆各族群投給各黨的機率（用來算選民流向的升降） |
| `refl` | 反思學習單三題的作答文字 |
| `bankrupt` | 是否破產 |
| `filter` | 政策分類篩選（目前畫面上沒有篩選按鈕，見 §6） |

### 2.5 計算核心

| 函式 | 作用 |
|---|---|
| `costOf(id, 黨)` | 政策成本，依政黨能力折扣（最低 1；省錢政策不折扣） |
| `money(g)` | 某黨政見的收入、既有方案支出、新提案支出、結餘 |
| `sat(g)` | 某黨政見讓每位島民的滿意度：稅率＋事件＋政策（乘上事件加成）＋理念符合度對基本盤的影響＋刪減的反彈＋執政黨被究責（貧窮與民怨）＋陳情是否回應＋赤字懲罰 |
| `votes()` | 每位有投票權的島民依六黨滿意度以 softmax 機率分票，乘上選民權重，加上質詢回答的加減，得到得票率 |
| `aiPlatform(g)` | 電腦對手依 `PREF` 偏好加隨機量挑政策、決定稅率、新右派與第三條路會刪減既有方案 |
| `island()` | 把所有實施中方案的 `fx` 加總，得到全島指標與貧窮率 |
| `islandMood()` | 島民對「目前實施中方案」的累積感受（新聞頁的島民現況） |
| `confirmGov()` | 確定執政黨後：寫入歷史、實施政策、更新經濟、國債、民怨與危機，切到下一屆 |
| `regime()` | 依實施中方案與全島指標，判斷最後最像哪一種福利體制 |
| `scores()` | 計分：累計得票率＋每屆執政 10 分＋每項政黨目標 15 分；破產全歸零 |

## 3. 意識形態：目前程式 vs. 七種觀點

**七種觀點的改版尚未完成，也尚未開始寫程式。** 目前程式仍是六個政黨的舊分類：

| 教學主軸要求的觀點 | 目前程式 | 狀態 |
|---|---|---|
| 1. 社會民主觀點 | `ds`「民主社會主義」：口號「福利是公民權利，不是施捨」，能力為普及化 | **名稱與定位不一致**。內容較接近社會民主，但名稱是民主社會主義，需要改名並重新檢視理念、能力與目標 |
| 2. 新右派 | `nr`「新右派」：小政府、大市場；市場化與財政改革政策成本 −1 | 已有 |
| 3. 第三條路 | `tw`「第三條路」：權利與責任、福利是跳板；選擇式政策成本 −1 | 已有 |
| 4. 馬克思主義 | 無 | **缺少**。沒有政黨、能力、目標、偏好權重、基本盤，也沒有對應的政策標籤或質詢卡 |
| 5. 女性主義 | `fe`「女性主義」：照顧公共化；照顧類成本 −1、效果 ×1.25 | 已有 |
| 6. 新社會運動 | 無 | **缺少**。相關議題（移工、原住民、身障、反歧視）散在政策與島民中，但不是一個可選的觀點 |
| 7. 綠色主義 | `gr`「綠色主義」：碳稅、綠色政策成本 −1 | 已有 |
| （清單外） | `co`「保守主義」：家庭與社區互助；家庭與公私協力成本 −1 | 不在七種觀點清單內。之前為了政治平衡加入。**保留、移除或改造需要老師決定** |

另外：

- 結局的四種福利體制（`REG`）是 Esping-Andersen 三分法加東亞生產主義，**它們是體制類型，不是意識形態**，七觀點改版時不必一對一對應。
- 政策目前**沒有**「國家／市場／家庭／社區分別負擔多少責任」的資料欄位，只能從標籤間接推（市場化→市場、家庭→家庭、公私協力→社區、普及式與社會保險→國家）。教學目標要求呈現責任分配，所以這個欄位要由 Claude 補進資料，美術再依此設計（見 ART_INTEGRATION.md §3.2）。

## 4. 提案、承諾、通過、實施與成果：程式實際怎麼區分

教學目標要讓學生看到「提案、實施與實際成果的差異」。程式目前的區分如下，**有一半尚未實作**：

| 階段 | 程式中的對應 | 狀態 |
|---|---|---|
| **提案** | `S.platforms[g]`：每黨本屆的稅率、新增政策、刪減方案。在 budget 畫面編列，開票後只有執政黨的提案會實施 | 已有 |
| **承諾** | 質詢回答（例如「下屆我們會推動移工勞動保障」）只立即改變得票與國債，**之後不會被追蹤**，也不會因跳票受罰 | **未實作**。目前沒有「承諾」狀態 |
| **通過** | 沒有立法表決。得票最高的黨直接執政，提案**全部**自動實施。唯一的「通過」門檻是第 3 屆公投（同意多於不同意，且同意達有投票權者 1/4），通過就實施，不管誰執政 | **部分**。只有公投有通過／不通過 |
| **實施** | `confirmGov()` 把執政黨的新增政策寫進 `S.enacted`，刪減的移出；成本鎖定為執政黨的折扣價；一次性政策只影響經濟動能，不列入實施中方案 | 已有 |
| **成果** | `island()` 把實施中方案的 `fx` 加總成全島指標與貧窮率；貧窮率累積成民怨；結局用 `regime()` 判斷福利體制 | **部分**。成果在下一屆**立即且必然**出現，沒有落差、延遲、執行失敗或非預期後果 |

因此目前**沒有**以下教學目標需要的機制：

- 「提案說的」與「實際做到的」之間的落差（例如長照券在偏鄉沒有業者，只出現在台詞裡，數值上照樣生效）。
- 第三屆之後，前期政策產生的後續影響與新的價值衝突（目前第 3 屆是公投，不是後果回顧）。
- 島嶼畫面隨實施中方案改變（目前島嶼插畫只隨事件改變天氣，見 ART_INTEGRATION.md）。

### 6.2 尚未完成

- 七種觀點改版（§3）。

- 遊戲內的「略過動畫」開關（目前只依系統的減少動態設定）。

### 6.3 已知問題（依程式碼）

1. **政策分類篩選是殘留程式**：`FILTERS` 常數與 `filter` 動作還在，但 budget 畫面沒有渲染篩選按鈕。之前改成手牌制後就沒有用到。
2. **輪盤角度寫死 8 等分**：`spin()` 用 `i*45+22.5` 計算停點，假設事件剛好 8 個。若增減事件，停點會和抽到的事件對不上，必須一起改。
3. **畫面全部用 innerHTML 重畫**：每次操作都重建整個 `#stage`，CSS 進場動畫（`rise`、`bump`）會在每次重畫時重新觸發；也代表外部動畫元件若掛在 `#stage` 裡，會在下一次 `render()` 被清掉（見 ART_INTEGRATION.md §7）。
4. **`rDemo` 在畫面函式裡修改狀態**：`S.wmod` 在渲染人口變遷畫面時才設定。目前流程不會出錯，但之後若重排流程要注意。
5. **輪盤轉動 3.5 秒無法略過**（減少動態模式下會直接跳過）。
6. **手機寬度 ≤420px 時，頂部隱藏貧窮率與屆數進度**（`styles.css` 第 309 行），手機玩家看不到貧窮率。
7. **成果沒有延遲**：所有政策在執政的下一屆就完全生效（§4）。
8. **作答不保存**（§5）。
9. **AI 對手與得票有隨機性**，同樣的選擇每局結果不同；沒有固定亂數種子，無法重現特定局面。
10. **字型依賴 Google Fonts CDN**：學校網路若擋 Google，標題會退回系統字型，海報感會減弱。
11. **插畫中有少量烘焙在 SVG 裡的文字**：島嶼插畫的「投票所」招牌、各處的「卜」字印章。輪盤上的事件名稱雖在 SVG 中，但由資料產生，可編輯。

## 8. 共同遵守的教學主軸

1. 首要目的：讓學生認識與比較社會民主觀點、新右派、第三條路、馬克思主義、女性主義、新社會運動、綠色主義。
2. 故事、畫面與動畫都要服務於理解：**福利責任由誰承擔、政策選擇、資源分配、價值衝突**。
3. 不把任何觀點畫成好人或壞人；同一個人物可以對不同觀點的政策有好有壞的反應（目前資料已是雙向台詞）。
4. 跨觀點的選擇不是錯誤。目前程式中「違背理念」只代表基本盤會流失，介面用語也不應暗示學生選錯。
5. 文字、政策名稱、數值保留為可編輯的介面文字，不烘焙進插畫。
6. 動畫用來解釋因果，必須可略過，並支援減少動態效果。

## 1. 現況總覽：目前沒有任何圖片檔

目前遊戲**所有圖像都是程式即時產生的 inline SVG**，沒有 PNG、JPG、外部 SVG 檔、Lottie 或影片。也就是說：

## 3. 第一階段三個關鍵畫面：現況與 Claude 能提供的資料

### 3.1 島嶼主畫面：呈現實際實施政策留下的變化

**現況**：`landscape()` 只依事件（`SCENE` 的 11 個鍵）改變天空與天氣，島上的房子、投票所、燈塔、樹**固定不變**，不反映任何實施中的政策。

**Claude 可提供的資料**（目前狀態中已有，可直接傳給畫面）：

```js
{
  round: 0-4,
  event: 'e1'...'e8' | null,          // 本屆事件
  enacted: [{ id:'p6', name:'長照公共服務網', tags:['univ','care','old'] }, ...],  // 實施中方案
  island: { poverty, pov, dec, str, def, stg, env, emp },   // 全島指標
  eco: 數值,  debt: 數值,  unrest: 0-100,  crisis: 0-3
}
```

**整合需求**：

- 插畫要能依「實施中方案」增減元素。請以**政策 id 或標籤**為鍵定義圖層或元素（例如托育中心、長照據點、社會住宅、屋頂光電、公車、工廠擴建、社區共餐），交回時附對照表。共有 53 張一般政策，不必每張都有圖；建議先以 13 種標籤或少數代表政策為單位。
- 元素要能疊加：同時實施 10 項以上政策時，畫面仍要可讀。
- 政策名稱、數值不要畫在圖上；需要標示時由 Claude 用 HTML 文字疊在圖上。
- 目前畫布比例：無島民時 400×230，含島民列時 400×310（`preserveAspectRatio="xMidYMid slice"`，會裁切兩側）。若新設計要改比例，請在交回時說明，Claude 調整版位。

### 3.2 政策選擇畫面：讓成本、受益者、責任分工與理念容易比較

**現況**：每張政策卡（`.pol`，`rBudget()` 527 行起；CSS 190 行起）是 HTML 元件，內容依序為：政策名稱、成本硬幣（含折扣刪除線、「省 N」）、標籤列（分類、符合／違背理念、事件加成、陳情、本屆限定、一次性、帶動經濟、已實施）、說明、受益／受損島民晶片（最多 +3 位、−2 位）。

**手機實際尺寸**：卡片寬 358px、高約 125px（內容多時更高）；桌面 2–3 欄、約 352×149。

**缺少的資料**：「國家／市場／家庭／社區各負擔多少責任」目前**沒有欄位**。Claude 會在資料中新增，暫定格式如下（數值與格式可協商）：

```js
resp: { state: 0-3, market: 0-3, family: 0-3, community: 0-3 }
```

**整合需求**：

- 卡片上的所有文字與數字維持 HTML，美術提供版型、圖示、色彩與狀態樣式（未選、已選、已滿、停用、陳情、事件限定）。
- 需要的圖示（建議 SVG，單色可由 CSS 換色）：13 種政策標籤、4 種責任主體、成本／省錢、受益／受損。
- 必須能在 358px 寬內並排比較；文字放大到 110% 仍不重疊。
- 「違背理念」的視覺不要做成錯誤或警告樣式（見 HANDOFF.md §8）。

### 3.3 第三屆政策後果場景

**現況：不存在。** 第 3 屆目前是公投畫面（`rRef`）。程式中沒有「回顧前期政策成果與新問題」的畫面或資料。

**Claude 會負責補的邏輯與資料**（尚未實作，格式為草案）：

```js
{
  sceneKey: 'consequence',
  enactedSince: [{ id, name, byParty, round }],     // 前兩屆實施的政策與執政黨
  outcomes: [{ citizenId, policyId, kind:'benefit'|'gap'|'newProblem', text }],  // 誰受益、哪裡有落差、出現什麼新問題
  conflict: { title, sides:[{ view, text }] }       // 由此引出的價值衝突
}
```

**整合需求**：

- 以人物與場景呈現，文字（`text`、`title`）由 Claude 的資料提供，畫面要留可容納 2–4 行中文的對話或說明區。
- 同一張場景要能對應不同的政策組合（每局實施的政策都不同），因此建議由可組合的人物、姿勢與背景元素構成，而不是一張固定插畫。
- 這個畫面插入的位置（公投之前或之後、是否取代某個畫面）尚未決定，需老師確認後由 Claude 調整流程。

## 4. 版面限制

### 4.1 手機（主要目標）

- 設計基準 390×844；最窄需支援 360 寬。
- 左右邊距 16px（含 safe-area），內容寬約 358px。
- 頂部 HUD 黏在頂端，高約 63px；底部操作列固定，高約 86px（含 safe-area）。主要內容在兩者之間捲動，**插畫與動畫不能被它們遮住關鍵部分**。
- 寬度 ≤420px 時，HUD 會隱藏貧窮率與屆數進度。
- 按鈕最小高度 48px。
- 建議直向持手機。

### 4.2 桌面與平板

- 內容最大寬度 1080px，置中。
- 斷點：640px（政黨卡、政策卡變 2 欄）、760px（標題海報與說明並排、新聞頁輪盤與新聞並排、對話與公投兩欄）、960px（3 欄）。
- 實測 1280×800：標題海報 552×428、新聞插圖 736×423、政策卡約 352×149。

### 4.3 深色模式

程式依系統設定自動切換深色色票（`styles.css` 13–20 行）。目前插畫的天空、海、島嶼顏色寫死在 SVG 裡，深色模式只在少數天氣下變暗。新素材請說明：深色模式沿用同一張圖，或提供深色版本。

## 6. 動畫原則（必須遵守）

1. 動畫用來**解釋因果**（例如：這項政策實施後，誰的生活改變了、錢從哪裡來），不是裝飾。
2. 每段動畫都要**可略過**：點擊或按鍵即跳到結束狀態。Claude 會在遊戲內新增「略過動畫」設定，請把略過當成必要行為設計。
3. 系統開啟減少動態效果時，提供靜態或極簡版本，**資訊不能因此消失**。
4. 動畫期間不鎖住閱讀；關鍵資訊在動畫結束後仍留在畫面上。
5. 單段建議不超過 3 秒；連續出現時要能一起略過。

## 7. 素材與元件的替換方式

### 7.1 靜態素材（圖片）

建議資料夾與命名（可協商，請交回時確認）：

```
assets/
  characters/{citizenId}_{expression}.{svg|webp|png}   例：ma_happy.svg
  scenes/{sceneKey}_{layer}.{svg|webp|png}             sceneKey：hero, e1–e8, ref, demo, consequence
  policy/{policyId 或 tag}.svg                         島嶼上的政策元素
  icons/{name}.svg                                     標籤、責任主體等圖示
  manifest.json                                        素材清單：檔名、尺寸、錨點座標、對應的 id
```

Claude 的整合方式：把 `face()`、`landscape()` 改為依 manifest 讀取素材，原本的 SVG 產生程式保留為後備（素材載入失敗時使用）。

### 7.2 獨立動畫元件

目前畫面每次操作都用 innerHTML 整個重畫 `#stage`，掛在裡面的元件會被清掉。因此 Claude 會提供一個**不會被重畫的容器**，並由主程式呼叫元件。以下是 Claude 這邊需要的**最小介面**（草案，名稱與形式可協商，不限定實作技術）：

```js
// 元件提供
mount(container, options)     // options: { reducedMotion: boolean, theme: 'light'|'dark' }
play(name, data) → Promise    // 播放某段動畫；結束或被略過時 resolve
skip()                        // 立刻跳到結束狀態
setState(data)                // 不播動畫，直接顯示某個狀態（例如島嶼目前實施的政策）
destroy()

// 主程式在 §5.2 的時間點呼叫 play() 或 setState()，data 為 §3 列出的 JSON
```

交回元件時請附：入口檔、相依套件與版本、所有 `name` 與其所需 `data` 欄位、檔案大小、在減少動態模式下的行為。

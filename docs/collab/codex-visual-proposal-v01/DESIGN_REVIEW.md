## 設計選擇

推薦：繪本式島嶼與人物，加上清楚的編輯式介面。保留紙色、深墨框線、暖色與海島辨識度；把閱讀區的紋理降到很淡。

替代方向：A. 延續原有 SVG 並精修，體積小、較易整合，但插畫變化較有限。B. 整頁大插畫，故事感強，但文字更新、載入與手機閱讀成本較高。本提案採混合方式：插畫作場景，文字與控制項由 HTML 呈現。

概念圖中的圖片與文字是整張點陣示意，不可直接切成正式操作介面。後續製作應另出無字、可分層的場景與人物素材；文字、資料及按鈕以 HTML/CSS 重建。

## 圖稿必須校正的地方

1. 左下「七種觀點」下方誤放居民頭像。正式版改為七種觀點的完整文字入口，人物區另標「島民」。居民不是意識形態的化身，也不固定對應某黨。
2. 圖片自行添加的「每一項政策都是為了讓島上的人過更好的生活」等文案不列為定稿。建議標題下改為「看見政策實施後的變化與取捨」。
3. 所有托育故事、據點及成果都是示例。必須由已實施政策與後續事件資料支持才出現，不以選牌、勝選或標籤直接推定生活已改善。
4. 左側虛線據點僅代表可切換的「提案預覽」；預設主畫面只呈現已實施狀態。若尚無實施／成果分階段資料，畫面只寫「已實施」，不得擅自寫「已完成」或「已見效」。
5. 第三畫面的三張窄選項只是構圖示意。360–390px 正式手機版改為三張全寬縱向卡，桌面才並排，保留說明與至少48px操作高度。
6. 數值欄位的橫線表示概念稿未帶資料，不代表0。正式版空值顯示「未提供」。圖中任何數字均非新平衡規格。
7. 不採用責任分工0–3數值長條，除非教師另有定義與判準。本提案採「誰提供、誰負擔、服務對象」文字角色，避免把質性分類偽裝成測量分數。

## 畫面一：島嶼與政策痕跡

目的：讓學生區分提案與實施，回顧前期選擇。島嶼是學習資訊入口，不新增另一套操作系統。

- 頂部始終可見第幾屆與總屆數；國債、經濟、民怨精簡呈現，其餘指標可展開。
- 固定底圖與有限圖層：交通、照顧服務、住宅、能源、社區設施。先以具體政策對照，再以可說明的資料規則聚合。
- 勞動權利等制度不可全部畫成建物；用人物活動、服務動線或文字標記表達。
- 同類政策多項實施時合併同一服務據點，點開列出相關政策，不重疊畫十幾棟建物。
- 主圖後立刻呈現「本屆觀察」，用成果與落差各一則帶入議題。
- 七種觀點使用平等大小的文字入口，不用居民肖像，也不以顏色作唯一識別。

可沿用資料：S.round、S.enacted、S.event；指標由 island() 及現有狀態提供。
待 Claude 補充：明確的政策與場景元素對照、提案預覽模式；若呈現實施時間／成果，需資料支持。
桌面：島圖與觀察面板左右排列；手機保持單欄。

## 畫面二：政策比較

目的：讓學生先看見政策如何安排福利責任，再查看理念說明。

- 把完整島民橫列、能力與目標、既有方案收進可展開區，避免第一張政策牌出現在長篇資訊之後。
- 頂部保留本屆議題、一行觀點名稱、已選張數與精簡財政摘要。
- 政策卡先呈現名稱、狀態、成本、做法；接著是提供者、負擔者、服務對象。展開後才呈現完整利弊與觀點關聯。
- 區分「預期改善」與「已出現成果」。編政見時使用前者。
- 「為什麼與這些觀點有關」允許多個關聯觀點與理由，不把一張政策硬綁一種理論。
- 比較功能手機建議兩項方案逐列對照或可切換閱讀；禁止以358px內容寬硬塞多欄小字。
- 圖中的待提案、已選、已實施需文字狀態。選中採框線與勾選，不只變色；與理念有張力採中性說明，不做答錯警示。

可沿用資料：政策 id/name/d/tags/cost、costOf、fx/cit（維持原有語義）、S.platforms、S.enacted。
待 Claude 補充：提供者、資金負擔者、適用對象、觀點關聯理由、生效時間；這些欄位不可由美術依名稱自行猜測。資料未提供時可顯示「待補充」，不阻擋既有遊玩。
桌面：政策列表加一個比較側欄，避免同時展開所有細節。

## 畫面三：第三屆政策後果

目的：由既有政策帶出價值衝突，保持七種觀點為主軸。

- 建議位置：第三屆新聞揭露後、公投前；由 Claude 評估與事件邏輯後確定。這是新設計提案，不是已存在的phase。
- 順序：前期實施了什麼 → 一項已見成果 → 一項服務落差或新需求 → 下一步的替代解法。
- 主圖使用同一居民與場景延續；不以壞天氣、醜化人物或紅綠答案暗示哪個觀點比較正確。
- 三種方案先看做法，再比較福利責任安排與價值取捨。不要把政府／市場／社區簡單等同為三個固定政黨。
- 故事內容只依實際政策／事件資料顯示；無符合案例時提供一般回顧，不編造玩家做過的事。
- 這一段若增加約1分鐘，應同時縮短既有重複提示，維持原先約20分鐘的整局目標。

待 Claude 補充：enactedSince、outcomes、conflict、後續選項及選擇結果；保存來源政策ID、回合、執政者，區分玩家與其他黨的政策。
桌面：成果與落差並列、方案列在下方；手機依閱讀順序堆疊。

## 動畫分鏡草案

| 觸發 | 動作 | 建議時長 | 略過／減少動態後保留 |
|---|---|---|---|
| 執政政策寫入後 | 新服務圖層淡入並顯示「已實施」 | 0.8秒 | 完整新島圖、政策名稱與狀態 |
| 切換提案預覽 | 虛線輪廓淡入；明示「預覽」 | 0.2秒 | 虛線與文字，不混同已實施 |
| 卡片加入政見 | 按鈕勾選與已選數同步改變 | 0.15秒 | 已選狀態；不把資金動畫當作真正支出 |
| 進入後果場景 | 政策來源、成果、落差依序淡入 | 共1.8秒 | 三段完整資訊與比較入口 |
| 人口變遷 | 前後數字及長條平順變化 | 0.6秒 | 保留前後值及變化說明 |

動畫不鎖住閱讀、每段可略過，不使用無限循環吸走注意力。不把微笑直接當成生活改善指標；現有支持度頭像與故事成果應分開標示。

## 整合上的關鍵要求

- render() 每次重建 #stage，長時間存在的島嶼動畫不可直接依附在會被清空的節點。由 Claude 決定保留容器或明確銷毀重建。
- 待正式製作元件時可採 mount/play/skip/setState/destroy 介面；play 在略過、取消與正常結束都要能完成，不阻塞回合流程。
- 重畫不能重播已看過的政策實施動畫；用政策變更事件而不是任意render作觸發。
- 優先 HTML/CSS 與可分層圖片或SVG，不增加大型動畫框架。Artifact素材載入與大小限制以實際發布驗證為準，不能把交接文件的待驗證資訊當成已測通。
- 文字至少以16px為預設起點、互動目標至少48px；後續需在360px、390px、桌面、文字放大、減少動態與鍵盤操作下驗證。本次未做這些執行測試。
- 深色模式採深色介面搭配保留原色插畫卡；不能直接反相人物與場景。
- 寄信與作答保存仍由 Claude 負責；美術工作不構成該功能已完成。
